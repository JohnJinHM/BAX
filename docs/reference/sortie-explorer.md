# 出兵分析的展示口径

状态：生效 · 更新：2026-11-20

战后分析的交互组件为 `src/main/SortieExplorer.vue`。筛选与分组基于已归档 `MatchAnalysis.sorties`；统计与归属由 Rust 提供。

玩家与兵种使用复选框，可多选、全选或清空。队伍筛选保留另一队的勾选，重置恢复全部玩家与兵种。分区顶栏包含视图、筛选和缩放操作，在主页面滚动时保持置顶，到分区末尾结束吸附。视图切换使用 100–180ms 过渡，系统减少动态效果时直接切换。

## 时间与分组

- 按玩家、存续时间及队伍展开视图统一显示白色具体单位图标，不显示兵种符号或类别色条。没有对应资源时显示单位名称，不冒用其他图标。
- 自动批次按一个标记约 76px 对应的时间跨度合并相近记录，缩放或窗口宽度变化时重新计算；批次以首条时间锚定，避免链式合并整场。手动批次仍可选 5、15、30 秒。
- 一个批次保留各型号图标，重复型号标数量；同型号的回收与未回收记录分别显示，RTB 角标对应具体单位。较多型号按最多三列换行，碰撞分层使用完整组宽与组高。
- 单位 logo 固定为 44×24px；存续时间无 RTB 的普通单位最小宽度为 54px，有 RTB 的为 66px，共用 10px 的边框与留白，RTB 额外占 12px。缺少图标时显示单位名称。末端向内收纳，精确时间以详情为准。
- 总览上拖选区间，或用两个滑块调整起止；支持放大、缩小、前后平移和全局。累计出兵曲线的阴影表示所选时间范围，曲线仍是整场双方累计值，不受单位筛选影响。
- 筛选区间包含起止时刻；队伍直方图每格左闭右开，最后一格包含终点，确保边界记录只计一次。双方共用数量或净估算价值刻度。
- 开局使用普通时间筛选，可将起止都设为 0:00。当前 Rust 投影将开局前的出兵时间压到 0，无法恢复准备阶段的原始时间；这只是时间筛选，不推断初始购买配置。

## 数量、价值与状态

- 数量表示出兵记录数，同型号多次出兵分别计数。
- 净估算价值沿用现有成本估算：回收记录计数但价值为 0。兵种百分比为当前范围、当前筛选下的队伍净估算价值占比，分别四舍五入，可能不精确加总为 100%。
- 区间投入按出兵时间统计。存续模式额外显示区间之前出兵、区间内仍有存续记录的单位，因此横条数不等于区间新出兵数。
- 存续横条延伸至阵亡；没有阵亡记录时延伸至比赛时长或已知事件末端。无阵亡记录不等于证明存活。回收时间未知，仅显示出兵标记，不绘制存续条。已回收单位用右下角 10px 的游戏 Back to base 图标表示，图表下方只保留回收图标与“已回收”说明；不使用虚线边框。
- 转交单位归原出兵者，详情标明接收者。可切换是否包含回收；空投在详情中显示；未识别的玩家或单位显示 ID。

## 单位图标

`node scripts/import-unit-icons.mjs [Units.json 路径] [thumbnails 目录] [Back to base PNG 路径]` 从本地 BA-Units、BA-DeckEditor 和 BATV 导入。默认路径见脚本。只复制 Units 表实际引用且存在的缩略图，构建后离线可用。

ID 和名称都匹配时使用对应图标；ID 不同但规范化名称唯一时按名称匹配。出兵分析遇到名称冲突、目录未知或图片加载失败时显示单位名称，避免错配。来源见 [NOTICE](../../NOTICE.md)。

视图顺序为“按玩家 / 存续时间 / 双方合并”。时间线默认高 600px，拖动底部横向把手调整到 240–2400px；聚焦把手后可用上下方向键、Home、End 调整。高度写入 `ui.sortie.height`，切换比赛或重启后恢复。

保存高度只更新设置，保留当前视图、筛选、时间范围和单位选择。比赛列表只监听归档序号、比赛编号及阶段；战报按编号及战报状态监听，避免完整快照或同一场列表行对象被替换时重新挂载。

兵种构成条形图、图例、兵种筛选与区间统计统一按侦察、步兵、坦克、步战与反坦克车、运输车、补给、防空、火炮、直升机、固定翼、其他排列，颜色固定。图例用复选框；点击柱条只选中对应类型，可继续勾选其他类型。筛选与价值／次数切换使用约 240ms 图表过渡。图表轴以玩家 ID 区分行，显示名称。

兵种构成的 `ClassShare.value` 为累计出兵估算价值，包含后来回收的单位；`count` 为出兵次数。每次出兵分别计入，同一单位重复返场也分别统计。旧战报从已保存原文重新计算，重新打开即可生效。队伍／玩家净出兵价值、累计净价值曲线、单位明细的净价值与区间净投入仍扣除回收。两种口径分别用于观察使用构成与净投入。

## 验证

本轮结果见 [界面验收记录](../validation/sortie-explorer.md)。编组数量与 RTB 共用图标右侧的固定定位列，数量在上、RTB 在下，不随网格列宽移动。

`npm run test:ui` 检查同秒重复、缩放批次与型号／回收分组、批次边界、最小长度与末端边界、碰撞分层、时间分箱、回收价值和图标文件完整性；`npm run build` 包含前端类型检查和生产构建。

浏览器预览使用虚构对局 `/dev/main.html?tab=history&match=8999927`，覆盖开局密集出兵、回收、空投、转交、未知图标和长玩家名。真实游戏单位名称只用于图标验证，玩家与比赛信息仍为虚构数据。
