# 0.2 实机验收清单

状态：生效 · 更新：2026-11-17

0.2 的悬浮窗与提醒只能在真实的游戏画面上验收。这份清单同时覆盖[验证 1](../validation/README.md)（Overlay 实机兼容）和验证 2 里尚未完成的部分（对照画面倒计时、提醒只触发一次）。每项记下结果，填进对应的验证记录。

## 准备

1. 构建并启动：`npx tauri build --no-bundle`，然后运行 `target\release\bax-app.exe`。开发时也可以用 `npm run tauri dev`。
2. 第一次使用建议先导入历史：`target\release\bax.exe logs import`，悬浮窗才能显示“遇过几次”。
3. 记录环境：Windows 版本、显示器数量与各自的缩放比例、游戏的显示模式与分辨率。

## 悬浮窗显示与焦点

| 场景 | 操作 | 期望 |
|---|---|---|
| 窗口化 | 进入对局后按 Ctrl+Alt+B 隐藏、再按显示 | 悬浮窗出现在游戏上方；游戏不失去焦点，键盘鼠标操作不中断 |
| 无边框全屏 | 同上 | 同上 |
| 独占全屏 | 同上 | 记录实际表现：能否看到悬浮窗、显示时游戏是否最小化 |
| 锁定 | Ctrl+Alt+L 锁定后在悬浮窗位置点击、拖动视角 | 操作穿透到游戏 |
| 解锁 | 再按 Ctrl+Alt+L，拖动标题栏、点展开按钮 | 能拖动、能点；点击后游戏是否失去焦点（记录） |
| 位置记忆 | 拖到别处，退出 BAX 再启动 | 出现在上次的位置 |
| 多显示器 | 把悬浮窗拖到副屏，游戏在主屏 | 记录是否正常 |
| 不同缩放 | 在 100%、125%、150% 缩放的显示器上各看一次 | 文字清晰，窗口大小贴合内容 |
| 快捷键冲突 | 同时运行原型（它也注册 Ctrl+Alt+B/L）后启动 BAX | 主窗口“设置·快捷键”显示注册失败的原因 |

## 计时与提醒

| 场景 | 操作 | 期望 |
|---|---|---|
| 开局计时 | 准备阶段时对照游戏画面的倒计时 | 悬浮窗显示“准备 m:ss”，与画面相差 2 秒以内；记录实际差值 |
| 正式开局 | 准备阶段结束 | 悬浮窗转为正计时，阶段显示“对局中” |
| 提醒 | 在主窗口“提醒与计时”加一条 1:00 的提醒并保存 | 开局 1 分钟时响两声、悬浮窗闪烁并显示提示文字 |
| 不重复 | 提醒响过之后退出 BAX 再启动 | 不再响 |
| 中途打开 | 对局进行到提醒时间之后才启动 BAX | 不补发，主窗口显示“本场已错过” |
| 断线重连 | 对局中断网或用任务管理器结束游戏后重连 | 计时连续；提醒不重复 |
| 手动校准 | 在主窗口填入画面上的时间并校准 | 悬浮窗计时随之改变 |

## 资源占用（验证 5 的预备数据）

用任务管理器的“详细信息”页，记录 `bax-app.exe` 及其 `msedgewebview2.exe` 子进程的内存与 CPU，分四种状态：只有悬浮窗、打开主窗口、对局进行中、对局之间空闲。
