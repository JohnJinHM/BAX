# 原生固定区域 OCR 验证

状态：生效 · 更新：2026-11-19

## 分支和实现

独立分支 `codex/ocr-native` 合入了 `origin/main` 的 `33fc093`，合并提交 `e362fc8`；标准版 main 未修改。原工作区的未提交改动未带入本分支。

原生 C++ 工作进程使用 ONNX Runtime CPU 1.22.0、两个文字识别模型和系统 GDI/WIC；不分发 Python、OpenCV、NumPy 或检测模型。固定双侧五行区域内按颜色裁去装饰边缘；昵称低置信度时尝试二值化，等级先以黄色标签定位，再识别右侧白色数字。俄文作为主识别结果或备选文本进入已有候选匹配。模型初始化使用两个 CPU 线程。

## 识别与耗时

样本是一张用户提供的 3576×1987 双侧五行卡片截图，以及从它重采样得到的图片，不是四场独立游戏截图。每档同一常驻进程运行 11 次，排除第一次识别，对剩余 10 次计时；图片解码和模型初始化不计入识别耗时。CPU 两线程，不含截图采集与 BATrace 查询时间。

| 分辨率 | 接受卡片数 | 等级相对原图 | 昵称相对原图，忽略大小写 | 识别中位 / 最大耗时 |
|---|---:|---|---|---|
| 3576×1987 | 10/10 | 10/10 正确 | 基准 | 270 / 285 ms |
| 2560×1440 | 10/10 | 10/10 一致 | 10/10 一致 | 241 / 263 ms |
| 1920×1080 | 10/10 | 10/10 一致 | 9/10 一致 | 235 / 254 ms |
| 1280×720 | 8/10 | 接受的 8 个一致 | 接受的 8 个一致 | 188 / 208 ms |

独立进程内模型加载与预热约 197–210 ms，不含操作系统进程创建时间，也不是重启电脑后的磁盘冷启动。旧 Python 方案的历史预热数据约 1.03 秒，测试时的系统负载不同，不能当成严格配对基准。

1080p 有一个方框符号识别为字母 O。720p 的两个卡片因低置信度被拒绝；没有降低阈值强行补齐。缺字方框与同形异码无法从截图恢复真实 Unicode 身份，因此继续将 OCR 视为候选，日志 ID 为准。

## 回归与安装

- `cargo test --workspace`：209 项通过，包括本地候选优先、日志名单覆盖及 v5 数据库测试。
- Clippy `--workspace --all-targets -- -D warnings`、cargo fmt 检查通过；前端 13 项测试、类型检查、生产构建通过。
- 原生代码 `/W4 /WX` 编译通过；CTC 重复字符、JSON 转义、等级范围、像素归一化、区域边界等单元测试通过。
- 虚构的中英俄日 10 个昵称全部出现在主结果或备选中，等级均正确；俄文和日文目前是合成测试，不代表真实游戏全样本准确率。
- 空白、单侧名单、缺少黄色等级标签、超宽比例不发布名单；模型缺失明确失败。回归脚本不访问网络或本机游戏日志。
- NSIS 静默安装退出码 0，安装目录 EXE 的模型自检 `ready: true`。
- 安装后的应用以隐藏模式打开真实 v5 库的独立副本；90 名玩家、17 场比赛、1 条备注和 11 份战报全部保留，SQLite 完整性检查通过。随后写入虚构等待房间日志，确认该应用启动安装目录中的原生 OCR 子进程。正式数据未修改，测试进程已关闭。

## 范围与复现

只验证约 16:9 双侧五行卡片布局。不覆盖其他等待大厅布局、不同卡片排列、超宽屏、HDR 或真实游戏帧时间；原生截图采集仍需游戏内验收。未在干净 Windows 虚拟机验证，所需 MSVC DLL 已应用本地分发。

构建与同步方式见 [打包指南](../guides/packaging.md)，决策见 [ADR-0010](../adr/0010-native-fixed-region-ocr.md)。图片回归入口 `scripts/test-ocr-native.py`，原始截图、观察结果、构建和诊断日志均在独立工作区 `.local/`。
