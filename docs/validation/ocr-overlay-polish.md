# OCR 资源与界面修复

状态：生效 · 更新：2026-11-19

## 原因和修复

最近四场标准诊断日志记录 OCR 名单分别为 7、6、3、7 人，敌方计数都为 0；正式日志到达后每场 10 人资料请求全部成功。默认 Full Debug 输出目录的工作进程仍为旧 Python 包（9,305,270 字节），源码资源目录已是原生版。旧进程没有 `friendly` 字段，未知敌我不会发起远程查询，同时旧裁切规则漏人。Tauri 无安装包构建没有刷新已有 OCR 资源，主程序优先加载了旧文件。

Full 构建现在显式同步整个输出资源目录、逐文件校验并在输出目录运行自检；工作进程握手包含 `runtime=native`、`protocolVersion=1`，引擎拒绝旧协议。名单改为每个位置连续两帧稳定后发布，未满十人或敌我未知时继续采集，补齐后停止。身份稳定后保留，单场查询位置去重、12 次额度、一秒间隔和错误后停止仍有效；本地只有名字但没有资料时继续查询。

## 页面与悬浮窗

- 比赛记录固定左侧列表，删除重复标题，弃赛标记使用“弃”。
- 玩家查询在数据库中先筛选排序再分页，默认本机、同场最多、最近见过；支持备注、同场、ELO 筛选和最近、ELO 升降序、名字排序。
- 出兵时间线可拖动或通过键盘调整高度，保存到 `ui.sortie.height`。视图和图例口径见 [出兵分析](../reference/sortie-explorer.md)。ResizeObserver 中的宽度和图表更新推迟到下一帧，避免布局回调循环。
- 自动展开设置存于 `ui.overlay`：`autoExpand=true`、`collapseBeforeBattleSecs=60`、`resultDisplaySecs=10`、`animations=true`。已有设置通过默认值补齐。选图选卡及进入准备阶段前展开；准备剩余时间到阈值时收起；结束后展开。自动行为不覆盖保存的手动展开偏好，不改变隐藏、锁定和鼠标穿透设置。
- 赛后分数读取本场已归档战报的 `OldRating/NewRating`，显示本机变化和双方各人变化。完整比赛首次战报尝试提前到结束后 3 秒、10 秒，之后沿用一分钟及更长重试；准备阶段取消仍跳过。十秒时未取得分数也会收起，分数到达后再展开一次并完整展示十秒。新比赛隔离旧结果，重启不重播超过两分钟的旧结束提示。
- 展开收起约 240ms，均分和加分计数约 420ms；用户动效开关及系统减少动态效果偏好均生效。

## 验证

使用用户提供截图离线复现：旧工作进程会漏人、没有敌我字段，甚至读到悬浮窗文字；新工作进程原尺寸 3839×2159、2560×1440、1920×1080 均读取 10 人，1280×720 读取 9 人。各尺寸预热后采样十次，原尺寸中位数约 204ms。四语合成样本十个昵称和等级通过，五项负例通过。此结果不保证低分辨率、特殊字符昵称或所有布局均可识别。

本地证据位于 `.local/fixes-20261119/`；真实玩家名称、比赛编号和原始日志不入库。

- Full Rust workspace 测试 218 项、Lite 测试 208 项通过；两种配置 Clippy 全目标零警告。
- 前端 20 项测试、类型检查和生产构建通过。新增测试覆盖全库筛选与分页、本机排序、原生握手、部分名单补齐、未知敌我补齐，以及自动收起、延迟加分、手动覆盖、旧场次启动和自定义时间。
- 浏览器虚构数据核对 1040px 窗口的固定侧栏、弃赛标记、默认玩家顺序及备注筛选。时间线通过键盘从 600 调为 660px，刷新后恢复；拖动把手从 240 调为 390px。核对存续视图只有回收图例，较窄战报内容区将下方统计与详情纵向排列。
- 悬浮窗预览验证准备阶段展开、阈值后收起、赛后加分显示和十秒后收起，手动再次展开保持。界面检测没有发现问题。

这些检查未启动真实游戏对局，仍需实际下一场核对前台采集、准备计时、真实 BATrace 分数到达时间及透明原生窗口在游戏上的动效。

默认完整版构建命令为 `pwsh -File scripts/build.ps1 -Mode Dev -Edition Full`。开发服务器使用现有依赖时可加 `-SkipNpmInstall`。程序路径是 `target/editions/full/debug/bax-app.exe`，配套 `ocr-runtime/`；此次构建日志保存在 `.local/fixes-20261119/full-build.log`。
