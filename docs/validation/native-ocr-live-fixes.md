# 原生 OCR 实机反馈修复

状态：生效 · 更新：2026-11-19

分支：`codex/ocr-native`。承接 [原生 OCR 验证](native-ocr.md)。真实截图和日志只保留在本机 `.local/` 或用户提供的位置。

## 日志结论

实机诊断中出现一次 `players.search` HTTP 429。另一场出现 30 次正式玩家资料请求超时（10 人、每人最多三次），后续场次又有 10/10 成功记录。证据足以说明需要减少 OCR 请求，不能证明全部超时都由限流导致。

## 修复约定

- 连续两次相同的非空识别结果锁定本场名单；比赛 ID 和发现时间共同标识一场比赛。切换选卡、失去前台或日志文件变化不会解除锁定，也不会清空名单重新查询。进入下一场才重置。
- 通过卡片标题条颜色识别敌我，不假设左侧恒为敌方。队友和敌我未知的卡片只匹配本地资料，不调用 OCR 搜索或资料 API。
- 敌人仍按昵称和等级、本地资料优先选择候选。远端查询串行，相邻 OCR 请求至少间隔一秒，每场最多 12 次 HTTP 请求，每个位置至多尝试一次。错误后本场停止 OCR 网络查询，保留识别结果等待日志；不循环重试。
- 收到 429 后，同一客户端的克隆共享冷却期，取服务端 Retry-After 和 30 秒的较大值。OCR 已取得的按 ID 查询资料可在 120 秒内被正式 ID 请求消费一次，避免紧接着重复查询；OCR 身份猜测仍不写入数据库。
- OCR 和日志名单使用相同的名单表格。我方、敌方按语义分组；候选只显示观察到的昵称和等级，不展示或链接候选 ID。日志名单到达后整体采用正式资料。尚无昵称的正式玩家显示“资料读取中”，不回退为 ID。
- 固定区域从按图片高度缩放改为按图片宽度缩放、垂直居中，修复下方行逐渐偏移的问题。

## 验证

用户本次截图左右各五张卡片。修正后读取 10 张，左侧为队友、右侧为敌人；此前缺失的第五行恢复，右侧第四行等级从误读 19 修正为 79。各行等级均与截图对应。昵称仍可能存在简繁字或外观相似字符差异，不能把截图视觉核对等同于账号身份确认。

原生离线回归包含四语合成卡片、5 个负例，以及该截图在原尺寸、2560×1440、1920×1080、1280×720 下的测试；每尺寸初始化后采样 10 次。四尺寸均读取 10 张，原尺寸热运行中位数约 218 ms。输出见 `.local/ocr-fix-native-tests.log`。

另用最初的加载界面截图复测：原尺寸、1440p 和 1080p 均读取 10 张，720p 读取 8 张，说明低分辨率下仍可能漏识别；本次修复不保证所有截图都完整读取。输出见 `.local/ocr-fix-old-screenshot.log`。

Rust workspace 测试 214 项通过；Clippy 全目标零警告。前端 16 项测试和类型检查通过，生成绑定已更新。新增测试覆盖队友零网络请求、每场锁定、请求间隔与额度、429 跨客户端共享冷却、OCR 资料复用，以及正式名单替换和不显示 ID。浏览器虚构数据预览核对悬浮窗和主窗口共用布局；界面检测未报告问题。

这些验证不代表所有游戏布局、俄日文真实昵称或线上网络故障已经覆盖。新版仍需下一场实测确认日志阶段与识别时机。
