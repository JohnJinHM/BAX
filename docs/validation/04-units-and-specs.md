# 验证 4：单位与专精口径

状态：进行中 · 更新：2026-11-17

## 要回答的问题

对照战报确认转交、空投、回收和分类的处理方式；确定逐场专精能否取得。通过依据见[项目规划](../planning/project-plan.md#可行性验证与推进顺序)。

这份记录完成了离线部分：用已有的真实战报分析字段的含义和规律。还没完成的是与游戏画面的对照（分类名称、空投与回收的表现），以及改装选项的成本。

## 环境

| 项目 | 值 |
|---|---|
| 日期 | 2026-11-17 |
| 数据 | 原型 BA-ELO-Overlay 本机缓存里的 307 份战报（183,898 个单位实例）与 1 份单位目录（462 项） |
| 方法 | 只读打开缓存数据库，脚本只输出汇总数字与单位名，不输出玩家信息 |

这些战报是原型查询过的比赛，以 5v5 排位为主，不代表全部比赛。

## 结果

### 单位实例的时间

`SpawnTime` 与 `DeathTime` 是 Unix 秒，不是相对开局的秒数。规划里“出兵节奏按 `SpawnTime` 相对比赛开始时间聚合”需要先减去战报的 `StartTime`。

| 观察 | 数值 |
|---|---|
| 全场最早出生 − `StartTime` | 中位数 3 秒，范围 2～12 秒 |
| （全场最晚的出生或阵亡 − 最早出生）÷ 比赛时长 | 中位数 0.998，5%～95% 为 0.990～0.999 |
| 没有 `DeathTime` 的实例（存活到结束） | 78,432 个，占 42.6% |
| 阵亡早于出生 | 0 |

准备阶段部署的单位在开局后两三秒统一出现，所以“开局部署”可以按出生时间落在开局后十几秒内来识别。

### 转交与归属

| 观察 | 数值 |
|---|---|
| 有转交的战报 | 125 份 |
| 转交实例 | 2,474 个 |
| 实例键出现在另一名玩家的 `UnitData` 里 | 2,474 个，单位类型与出生时间全部相同 |
| 实例键仍在转出者自己的 `UnitData` 里 | 0 |
| 两边都找不到 | 0 |
| 同一个实例键出现在两名玩家名下 | 0（共 183,898 个键） |

结论：`UnitData` 是比赛结束时各自名下的单位；`TransferredUnits` 记在转出者名下，键与接收者那边的实例相同。统计“谁出的兵”时，把转出的实例算回转出者；统计“谁在用”时按 `UnitData`。

### 分类

目录覆盖了全部 183,898 个实例。各分类的实例数：0 有 29,180，1 有 45,162，2 有 41,752，3 有 35,188，4 有 26，5 有 15,077，6 有 17,513。按目录里的单位名推断，0 是侦察（含无人机与狙击手），4 是机组、训练靶、舰艇等非作战单位；各 role 的含义见 [BATrace 接口参考·单位分类](../reference/batrace-api.md#单位分类)。

### 价值

按目录基础价格累加每名玩家的实例，与战报的 `TotalSpawnedUnitScore` 相比，比值中位数 0.76（5%～95% 为 0.61～0.88，样本 3,035 人次）。差额主要来自改装选项。规划的判断成立：单个单位的成本要解析选项，基础价格只能用于明确标注的估算。

### 无效值

单位实例的 `TotalDamageReceived` 出现 99 次 -1，`TotalSelfDamageDealt` 出现 57 次 -1；玩家的 `DLRatio` 也出现过 -1。统计时视为缺失。

### 专精

战报的比赛层和玩家层都没有名字含 spec 或 deck 的字段。逐场专精无法从战报得到；能用的只有玩家资料里累计的专精等级与经验。

## 结论

部分通过：转交归属、实例去重、时间换算、分类覆盖和无效值都有了明确的处理方式；逐场专精确认无法从战报取得，规划里“近期专精使用率”需要别的来源。仍待确认：分类名称与游戏内的对应、空投与回收实例在统计里的处理、改装选项的成本。

## 使用者的判断（2026-11-17）

使用者认为从 BATrace 取得的数据是准确的，与游戏画面逐项核对不再作为 0.4 的前提。0.4 直接采用战报的官方字段；仍然不能确定的只有单个单位的成本（接口没有改装选项的价格），界面上明确标为估算。

## 对设计的影响

- 0.4 的出兵时间线用 `SpawnTime − StartTime`；测试样本 `fixtures/batrace/match_report.json` 已改为 Unix 秒。
- 统计口径分“出兵者”（`UnitData` 减去接收的，加上转出的）与“使用者”（`UnitData`）两种，界面上要标明用的是哪一种。
- 兵种构成按 category 与 role 组合分组，category 3 里的补给车单独列出，不算火炮。
- 出兵价值只用战报的玩家级字段；单个单位的成本是估算：按基础价格加总后，等比例缩放到这名玩家官方的“出兵价值 − 回收价值”（参考 ba-dragon），玩家与队伍的总数因此和官方一致，界面明确标注。0.4 已按此实现（`bax-core::report`）。
- `WasRefunded` 是单位被回收（飞机返航、开局卖掉等），官方全额退款：每条记录算一次出兵，回收的不计入花费（据 ba-dragon 的说明）。
- 规划的“近期专精使用率”暂时搁置，除非找到逐场的数据来源（例如本机日志里的卡组名，但它可以自定义）。
