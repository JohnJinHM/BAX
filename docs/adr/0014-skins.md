# ADR-0014：皮肤是内置的 CSS 变量组

- 状态：提议
- 日期：2026-11-21
- 相关：[ADR-0004](0004-state-ownership.md)、[ADR-0006](0006-frontend-stack.md)、[项目规划·产品范围](../planning/project-plan.md#产品范围)、[皮肤变量](../reference/skins.md)

## 背景

规划把自定义皮肤列为 0.5 的内容：切换主题，调整颜色、透明度、字号与间距；首版开放到什么程度留待决定。ADR-0006 已经约定样式用 CSS 变量，皮肤只换变量。

开始做皮肤时，`theme.css` 只有一组变量，组件里还有十几处写死的颜色（选中行、胜负标签、悬浮窗的虚线边框）和二十多处写死的圆角；战后图表从 CSS 变量取色，但只在组件创建时取一次。现有界面定为“默认”皮肤，第一个可替换的皮肤参照游戏 HUD 的设计说明，需要的不只是换色：直角面板、选中项的窄边、导航的选中标记。

## 决定

- **皮肤是一组 CSS 自定义属性。** 默认皮肤就是 `src/shared/theme.css`；其他皮肤各占 `src/shared/skins/<id>.css` 的一个 `[data-skin="<id>"]` 块，只覆盖 `theme.css` 已经声明的变量，不写选择器规则，不改组件结构。皮肤目录在 `src/shared/skins.ts`。
- **变量分两层。** 基础变量（底色、面板、文字、强调色、队伍与状态色、圆角、字体）由每个皮肤直接给值；组件变量（导航选中、列表选中、本机玩家行、重要数值、分区标题标记、主窗口背景）默认由基础变量推出，皮肤需要不同的表现时单独覆盖。默认值为“不显示”的组件变量（透明的窄边、宽度为 0 的标题标记）不改变默认皮肤的布局。
- **变量写在 `[data-skin]` 上。** 切换皮肤就是改 `<html data-skin>`；设置页的预览块带自己的 `data-skin`，就地按那个皮肤渲染。
- **所选皮肤是界面设置 `ui.skin`。** 和其他界面设置一样由引擎保存、随快照分发，主窗口与悬浮窗同时切换，Rust 一侧不读。前端另在 `localStorage` 记一份皮肤 ID，只用于快照到达之前的第一帧；快照到了以后以快照为准，不认识的 ID 按默认皮肤处理。
- **图表随皮肤重新取色。** 从 CSS 变量取色的计算依赖当前皮肤，切换后重新生成图表配置。兵种分类的色板标识数据类别，不随皮肤变化。
- **首版只有内置皮肤。** 不加载用户提供的 CSS 文件或主题包。之后开放颜色、字号等个人调整时，在内置皮肤之上叠加变量覆盖，仍然只接受变量。

## 后果

- 组件里不再写颜色值和 6px、4px 的圆角，改用变量；更小的圆角写成 `min(3px, var(--bax-radius-xs))`，默认皮肤保持原样，直角皮肤随之变小。新增界面时同样遵守，`tests/skins.test.mjs` 检查皮肤文件只声明已有变量、目录与文件一一对应，并按 WCAG AA 检查每个皮肤的文字对比度。
- 皮肤能表达的东西以变量为限。需要新的视觉差异时，先在 `theme.css` 增加一个默认不改变现状的组件变量，再由皮肤覆盖。
- `localStorage` 里的皮肤 ID 只是第一帧的提示，不是设置的副本，不违反 ADR-0004。
- 皮肤文件随两个页面一起加载，每个皮肤一两 KB，对悬浮窗的体积影响可以忽略。皮肤需要系统没有自带的字体时随应用打包，`@font-face` 写在 `skins/index.css`，页面用到这个字体时才加载。

## 备选方案

- **允许用户放入自己的 CSS 文件。** 表达力最强，但任意 CSS 可以改布局、加载外部资源、遮住悬浮窗的锁按钮热区，升级时也无法保证兼容。等内置皮肤和个人调整用过一段时间、确实不够时再考虑。
- **每个皮肤一套组件样式。** 可以做出差异更大的界面，但每改一个组件都要同时维护几套样式，皮肤越多越难保持一致。
- **主题定义放在 Rust 一侧，以 JSON 下发。** 皮肤只影响展示，放进引擎没有好处，还要为每个变量写类型和默认值。
