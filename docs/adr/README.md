# 架构决策记录（ADR）

每条 ADR 记录一个对结构有长期影响的决定：当时的背景、选了什么、带来什么后果。架构文档描述现状，ADR 解释现状为什么是这样。

## 什么时候写

出现下面任一情况时新增一条：

- 选定或更换框架、存储方式、通信方式等难以回退的技术；
- 改变模块边界或依赖方向；
- 改变产品范围的边界，例如纳入或排除一类功能；
- 可行性验证得出了影响设计的结论。

实现细节、命名和可以随手改回去的选择不需要 ADR。

## 怎么写

1. 复制 [template.md](template.md)，命名为 `NNNN-简短英文标题.md`，编号顺延，不复用。
2. 状态从“提议”开始。项目负责人确认后改为“已采纳”，并更新上面的索引。
3. 已采纳的 ADR 不改写结论。决定变了就新增一条，把旧的一条状态改为“被 ADR-NNNN 取代”，正文保持原样。
4. 决定影响到架构文档时，在同一次提交里更新架构文档。

状态取值：提议、已采纳、已废弃、被 ADR-NNNN 取代。
