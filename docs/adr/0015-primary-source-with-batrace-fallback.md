# ADR-0015：游戏数据源优先，BATrace 补充与回退

- 状态：已采纳
- 日期：2026-11-21
- 相关：[数据源参考](../reference/batrace-api.md)、[兼容性验证](../validation/upstream-api-compatibility.md)

## 背景

BATrace 维护后，BAX 使用的 API 路由返回 HTTP 404，玩家资料与战报读取受影响。公开项目提供的游戏 API 和战报对象源已通过玩家资料、排位及自定义样本验证，但不能完整替代昵称搜索、单位目录和部分累计统计。

## 决定

在现有 `bax-batrace` 客户端内增加主源适配器，玩家基础资料和战报优先使用 `api.brokenarrowgame.tech` 与 `s3.brokenarrowgame.tech`。BATrace 补充缺失功能并作为失败回退。沿用现有领域类型和归档格式，字段转换、合并、数字精度检查均在客户端边界完成，数据库不迁移。

请求使用短期缓存和按对象的并发去重。游戏 API、战报对象源和 BATrace 分别处理限流与故障暂停，避免一个来源阻塞其他来源。引擎保留已有的刷新计划、持久缓存和战报归档。设置页及 CLI 通过少量公开样本手动检查各接口状态。

## 后果

主要读取路径减少对 BATrace 的依赖。主源已有字段优先，未提供的统计不合成为零；缺失补充字段保留本地旧值。所有来源失败时继续展示已有记录。

请求与合并逻辑更复杂，需要覆盖数据类型差异、部分失败、独立暂停、缓存过期和主源恢复。PvE 覆盖、历史保留期限与公开接口正式配额仍未确认，因此保留双源策略和可见的状态查询。
