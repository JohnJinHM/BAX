# ADR-0008：赛前 OCR 候选与日志身份分离

状态：已采纳 · 日期：2026-11-18

## 背景

等待室日志缺少完整玩家 ID。用户已授权按昵称与等级匹配候选，本地数据库优先，日志 ID 到达后更新；在独立分支开发。验证见 [赛前名单](../validation/pregame-roster.md)。

## 决定

- 用本机常驻 RapidOCR/ONNX CPU 工作进程识别游戏前台窗口，仅在日志提示赛前且无正式名单时采集。截图仅在内存中处理，不上传、不写盘。不读游戏内存，不注入游戏。
- OCR 工作进程输出昵称、等级与画面侧别；Rust 引擎负责候选排序、查询和快照。Python 环境与模型由安装脚本准备在用户数据目录，应用缺少运行环境时明确报告，不能静默伪装识别成功。
- 本地玩家当前名字与历史日志别名优先。同等昵称匹配时按等级差排序；无可靠本地候选才搜索 BATrace。ELO 不参与排序。平手、缺字、重号冲突保留未确认状态。
- 候选与正式 PlayerView 分开，不进入 Tracker，不写比赛名单、相遇记录或备注。日志名单到达后候选视图退出，按原 ID 流程加载正式资料。换局、退出、重连、关闭功能后丢弃晚到的 OCR/网络结果。
- 提供启停设置，默认启用；查询去重、有限并发、失败退避。OCR 运行环境按需启动并预热，常驻期间复用模型。

## 后果

安装增加本地 OCR 环境和模型。多语言同形字和同名同等级仍可能无法消歧；界面明确显示候选。首版支持已验证的双侧玩家卡片布局，其他画面识别不到时保留日志流程；实机选图布局需要验收。
